# Задание 1. Исследование моделей и инфраструктуры

## 1. Сравнение LLM-моделей

### Локальные Hugging Face vs облачные OpenAI / YandexGPT

#### 1.1 Качество ответов

Облачные модели демонстрируют более стабильное и предсказуемое качество ответов, особенно для сложных инженерных и регламентных вопросов

#### 1.2 Скорость работы

| Критерий               | Hugging Face                | OpenAI / YandexGPT         |
| ---------------------- | --------------------------- | -------------------------- |
| Задержка               | Зависит от GPU/CPU          | Стабильная, низкая         |
| Пропускная способность | Ограничен ресурсами сервера | Масштабируется провайдером |
| Пиковые нагрузки       | Требуют запас по железу     | Прозрачны для пользователя |

#### 1.3 Стоимость владения и использования

| Критерий             | Hugging Face             | OpenAI / YandexGPT    |
| -------------------- | ------------------------ | --------------------- |
| Начальные затраты    | Высокие (GPU, DevOps)    | Минимальные           |
| Операционные расходы | Электричество, поддержка | По мере использования |
| Масштабирование      | Дорого                   | Линейно по запросам   |

#### 1.4 Удобство развёртывания

| Критерий               | Hugging Face | OpenAI / YandexGPT |
| ---------------------- | ------------ | ------------------ |
| Скорость развертывания | Недели       | Часы               |
| DevOps сложность       | Высокая      | Низкая             |

#### Промежуточный вывод по LLM

Локальные LLM оправданы при строгих требованиях к изоляции данных

Облачные LLM оптимальны для MVP и быстрого внедрения

## Сравнение моделей эмбеддингов

### Sentence-Transformers vs OpenAI Embeddings

#### 2.1 Скорость создания индекса

| Критерий          | Sentence-Transformers | OpenAI Embeddings    |
| ----------------- | --------------------- | -------------------- |
| Индексация        | Быстро локально       | Зависит от сети      |
| Массовая загрузка | Хорошо масштабируется | Возможны rate limits |

#### 2.2 Качество поиска

| Критерий           | Sentence-Transformers | OpenAI Embeddings |
| ------------------ | --------------------- | ----------------- |
| Semantic search    | Хорошо                | Отлично           |
| Работа с техдоками | Хорошо                | Очень хорошо      |
| Многоязычность     | Зависит от модели     | Стабильно высокая |

#### 2.3 Стоимость
| Критерий  | Sentence-Transformers      | OpenAI Embeddings |
| --------- | -------------------------- | ----------------- |
| Стоимость | Бесплатно (инфраструктура) | Плата за токены   |

#### Вывод по эмбеддингам

Для больших объёмов документации и регулярной переиндексации локальные эмбеддинги экономически выгоднее

Качество Sentence-Transformers достаточно для корпоративного RAG

## 3. Сравнение векторных баз

### FAISS vs ChromaDB

#### 3.1 Скорость и производительность

| Критерий        | FAISS         | ChromaDB     |
| --------------- | ------------- | ------------ |
| Поиск           | Очень быстрый | Быстрый      |
| Индексация      | Очень быстрая | Быстрая      |
| Масштабирование | Ручное        | Более гибкое |

#### 3.2 Сложность внедрения и поддержки

| Критерий             | FAISS               | ChromaDB   |
| -------------------- | ------------------- | ---------- |
| Простота             | Очень прост         | Средняя    |
| Persistence          | Нужно реализовывать | Встроенная |
| Поддержка метаданных | Нет                 | Да         |

#### 3.3 Стоимость владения

| Критерий       | FAISS       | ChromaDB  |
| -------------- | ----------- | --------- |
| Лицензия       | Бесплатно   | Бесплатно |
| Инфраструктура | Минимальная | Чуть выше |

#### Вывод по векторным БД

FAISS - оптимален для MVP и учебного проекта

ChromaDB - лучше подходит для продакшена с ростом требований

## 4. Итоговые варианты архитектуры

### Рекомендуемая конфигурация сервера

#### Базовые оценки нагрузки

- ~25 000 документов (Markdown + PDF)
- До 200-300 запросов в день
- 5-10 одновременных пользователей

#### Рекомендуемые конфигурации

| Вариант     | CPU     | RAM       | GPU     | Назначение        |
| ----------- | ------- | --------- | ------- | ----------------- |
| Минимальный | 4 vCPU  | 16 GB     | -       | MVP, FAISS        |
| Оптимальный | 8 vCPU  | 32 GB     | -       | Продакшен без LLM |
| GPU-вариант | 8 vCPU  | 64 GB     | 1*A10   | Локальная LLM     |
| Enterprise  | 16 vCPU | 64-128 GB | 1-2 A10 | Полная изоляция   |

### Вариант 1. Облачный (рекомендуемый для старта)

- OpenAI / YandexGPT
- OpenAI Embeddings
- FAISS
- Docker + Compose

**Плюсы:**

- быстрый запуск
- минимальный DevOps
- высокое качество ответов

**Минусы:**

- данные уходят в облако

### Вариант 2. Гибридный (рекомендуемый для QuantumForge)

- Облачная LLM
- Локальные Sentence-Transformers
- ChromaDB

**Плюсы:**

- компромисс по безопасности
- контроль стоимости
- масштабируемость

**Минусы:**

- чуть сложнее архитектура

### Вариант 3. Полностью локальный

- Hugging Face LLM
- Sentence-Transformers
- ChromaDB
- GPU-сервер

**Плюсы:**

- максимальная безопасность
- соответствие аудитам

**Минусы:**

- высокая стоимость
- сложная поддержка

### Вариант 4. Продуктовый (будущее)

- Гибридная архитектура
- Мультитенантность
- Изоляция данных по командам
